# 多应用邮件服务集成指南

> 本文档说明如何将邮件验证功能集成到多个应用中，共用一台邮件服务器。
>
> 创建时间：2026年2月7日
> 适用场景：多个应用共用一台邮件服务器

---

## 一、架构说明

### 1.1 多应用共享架构

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   应用A     │    │   应用B     │    │   应用C     │
│  (前端JS)   │    │  (前端JS)   │    │  (前端JS)   │
└──────┬──────┘    └──────┬──────┘    └──────┬──────┘
       │                  │                  │
       └──────────────────┼──────────────────┘
                          │
              ┌───────────┴───────────┐
              │   共用邮件服务器        │
              │  (Node.js + pm2)       │
              │   81.71.18.174:3000    │
              └───────────┬───────────┘
                          │
                    ┌─────┴─────┐
                    │  SendCloud │
                    │  邮件服务  │
                    └───────────┘
```

### 1.2 核心优势

- ✅ **节省成本**：一台服务器服务多个应用
- ✅ **统一管理**：集中监控邮件发送状态
- ✅ **灵活配置**：每个应用使用独立的邮件模板
- ✅ **易于扩展**：新增应用只需创建新模板

## 二、SendCloud 控制台配置（人工操作）

### 步骤1：为每个应用创建邮件模板

**操作路径**：SendCloud控制台 → 邮件发送 → 邮件模板 → 创建模板

**模板配置示例**：

| 应用名称 | 模板名称 | 调用名称 | 邮件主题 |
|---------|---------|---------|---------|
| 智能复盘助手 | 验证码模板 | `verify_code_template` | 【智能复盘助手】您的验证码是：%verify_code% |
| 应用A | 应用A验证码 | `app_a_verify_template` | 【应用A】您的验证码是：%verify_code% |
| 应用B | 应用B验证码 | `app_b_verify_template` | 【应用B】您的验证码是：%verify_code% |

**邮件内容示例**（应用A）：
```
尊敬的 %name%：

感谢您注册【应用A】！

您的邮箱验证码是：%verify_code%

⏰ 验证码有效期为 10 分钟，请尽快完成验证。

如非本人操作，请忽略此邮件。

---
应用A团队
官网：https://app-a.com
```

**关键要点**：
- ⭐ **调用名称**是唯一标识，代码中要用
- ⭐ 不同应用使用不同的**发件人名称**
- ⭐ 可以共用同一个 **API_USER & API_KEY**

## 三、邮件服务器配置（已支持多应用）

### 3.1 后端代码已更新

当前邮件服务器 (`email-server.js`) 已支持多应用，主要更新：

**接收参数**：
```javascript
{
    email: 'user@qq.com',           // 收件人邮箱（必填）
    verifyCode: '123456',           // 验证码（必填）
    templateName: '模板调用名称',    // 模板名称（可选，默认使用配置中的模板）
    fromName: '发件人名称'           // 发件人名称（可选，默认"智能复盘助手"）
}
```

**向后兼容**：
- 如果不传 `templateName`，使用默认模板
- 如果不传 `fromName`，使用默认发件人名称

## 四、各应用前端集成（AI代码操作）

### 4.1 应用A（智能复盘助手）- 已有代码

**文件**：`review-assistant.js`

**配置**：
```javascript
const EMAIL_SERVER_URL = 'http://81.71.18.174:3000/api/send-email';

function sendVerificationEmail(email, verifyCode) {
    fetch(EMAIL_SERVER_URL, {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json'
        },
        body: JSON.stringify({
            email: email,
            verifyCode: verifyCode,
            templateName: 'verify_code_template',  // 指定模板
            fromName: '智能复盘助手'               // 指定发件人
        })
    })
    .then(response => response.json())
    .then(data => {
        if (data.success) {
            alert('验证码已发送至您的邮箱，请查收！');
        } else {
            alert('邮件发送失败：' + data.error);
        }
    })
    .catch(error => {
        alert('邮件服务暂时不可用');
    });
}
```

### 4.2 应用B（新应用）- 需要添加的代码

**步骤1：添加邮件服务配置**

```javascript
// 后端邮件服务配置（共用同一台服务器）
const EMAIL_SERVER_URL = 'http://81.71.18.174:3000/api/send-email';
```

**步骤2：添加发送邮件函数**

```javascript
/**
 * 发送验证码邮件
 * @param {string} email - 收件人邮箱
 * @param {string} verifyCode - 验证码
 */
function sendVerificationEmail(email, verifyCode) {
    console.log('发送邮件请求:', { email, verifyCode });
    
    fetch(EMAIL_SERVER_URL, {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json'
        },
        body: JSON.stringify({
            email: email,
            verifyCode: verifyCode,
            templateName: 'app_b_verify_template',  // ⭐ 应用B的模板名称
            fromName: '应用B名称'                   // ⭐ 应用B的发件人名称
        })
    })
    .then(response => {
        console.log('后端响应状态:', response.status);
        return response.json();
    })
    .then(data => {
        console.log('后端响应数据:', data);
        if (data.success) {
            alert('验证码已发送至您的邮箱，请查收！');
        } else {
            console.error('邮件发送失败:', data);
            alert('邮件发送失败：' + (data.error || '未知错误'));
        }
    })
    .catch(error => {
        console.error('请求失败:', error);
        alert('邮件服务暂时不可用，请稍后重试');
    });
}
```

**步骤3：在发送验证码按钮点击时调用**

```javascript
// 示例：绑定发送验证码按钮事件
document.getElementById('send-verify-btn').addEventListener('click', () => {
    const email = document.getElementById('email-input').value;
    const verifyCode = generateVerifyCode(); // 生成6位验证码
    
    // 保存验证码到内存或sessionStorage（用于后续验证）
    sessionStorage.setItem('currentVerifyCode', verifyCode);
    
    // 发送邮件
    sendVerificationEmail(email, verifyCode);
});

// 生成6位数字验证码
function generateVerifyCode() {
    return Math.floor(100000 + Math.random() * 900000).toString();
}
```

## 七、故障排查

### 问题1：应用B收不到邮件

**排查步骤**：
1. 检查应用B前端代码中的 `templateName` 是否正确
2. 检查 SendCloud 中是否创建了对应模板
3. 查看邮件服务器日志：`pm2 logs email-server`

### 问题2：邮件发件人显示不正确

**排查步骤**：
1. 检查前端代码中的 `fromName` 参数
2. 检查 SendCloud 模板中的发件人配置

### 问题3：某个应用发送频率过高

**解决方案**：
- 在各自应用前端添加发送频率限制（如60秒只能发送一次）
- 或在邮件服务器端添加限流逻辑

## 八、安全建议

1. **API_KEY保护**：不要在浏览器端暴露 SendCloud 的 API_KEY（当前架构已保护）
2. **频率限制**：每个应用单独限制发送频率（建议60秒/次）
3. **日志监控**：定期查看 `pm2 logs` 监控异常发送
4. **模板审核**：SendCloud模板需要审核通过才能使用

## 九、扩展方案

### 方案1：每个应用独立 SendCloud 账号

如果应用之间需要完全隔离：
- 每个应用注册独立的 SendCloud 账号
- 邮件服务器支持多账号配置（需要修改代码）

### 方案2：添加更多邮件类型

除了验证码，还可以添加：
- 密码重置邮件
- 订单通知邮件
- 营销邮件（需要单独模板和调用接口）
